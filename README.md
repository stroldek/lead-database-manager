# Lead Database Manager — v0.1.2

**Тестовый шаг перед этапом 2:** реальное подключение вашего Telegram-аккаунта (QR или вручную), простой мониторинг чатов и комментариев каналов, тестовая база и выгрузка в Excel.

Цель шага — как можно раньше проверить на живом Telegram то, от чего зависит весь проект, а не строить остальное «на абстрактных значениях».

## Что умеет эта версия

| Блок | Что работает |
|---|---|
| **Аккаунт Telegram** | Вход по **QR-коду**; под QR кнопка **«Войти вручную»** (номер → код → пароль 2FA, если включён). Сессия хранится на сервере зашифрованной (AES-GCM). Выход из аккаунта одной кнопкой. |
| **Мониторинг** | Выбор групп, супергрупп и каналов из ваших чатов. Для канала читаются **комментарии** (они лежат в привязанной группе обсуждения). Условия — ключевые слова (без учёта регистра и «ё»). Работает по таймеру (интервал 15–3600 с) и кнопкой «Проверить сейчас». |
| **Тестовая база** | Один человек = одна запись, даже если он писал в нескольких чатах (счётчик «×N»). Повторная проверка тех же сообщений дубликатов не создаёт. Поиск, страницы, очистка с подтверждением. |
| **Excel** | `Имя · Ник · Номер телефона (нет → Nope) · Источник · Дата добавления в базу · Текст сообщения-триггера`. Время — Киев. |
| **Диагностика** | Кнопка проверяет по шагам: настройки сервера → база → загрузка библиотеки Telegram → сетевое соединение → шифрованное рукопожатие. Показывает, на каком именно слое остановка. |
| **Защита** | Вход в панель по ключу `ADMIN_TOKEN`; ограничение неверных попыток; ключи Telegram и сессия — только на сервере, в браузер не отдаются. |

## Чего пока нет (честно)

- Программа **только читает** выбранные чаты. Отправка сообщений, смена аватарки, просмотр и правка профилей — **не реализованы** в этой версии. Подключение технически даёт полноценную сессию, поэтому эти действия добавляются поверх неё; удаление аккаунта в программу заложено не будет.
- Номер телефона у человека виден только если он открыт его настройками приватности или человек есть в ваших контактах. Иначе в файле будет `Nope` — это поведение Telegram, а не ошибка.
- Разделы, фильтры, импорт, авто-чат и остальное — по плану ТЗ (этапы 2–12).

## Что проверено, а что нет

**Проверено автоматически (в среде разработки):** 33 теста логики и базы (реальные SQL-миграции на SQLite) + 12 шагов в настоящем браузере: вход в панель, ключи, QR, вход по номеру с неверным кодом и паролем 2FA, выбор чатов, поиск совпадений, Excel (файл открыт и сверен), очистка. Telegram в этих тестах — **имитация**.

**Не проверено и проверить без вас нельзя:** работа библиотеки Telegram (GramJS) внутри Cloudflare Workers с вашими ключами. В среде разработки нет выхода в интернет, поэтому реальное соединение с Telegram не запускалось. Для этого и сделана кнопка **«Диагностика»**. Если она покажет сбой — пришлите мне, какой шаг красный и что написано под ним: тогда по фактам выберем обходной путь.

## Развёртывание (всё в браузере, ничего не устанавливается)

> Названия кнопок в Cloudflare иногда меняются; суть шагов та же.

1. **База.** Cloudflare → Storage & databases → **D1** → Create database, имя `lead-database-manager`. Скопируйте **Database ID**.
2. **Таблицы.** Откройте базу → вкладка **Console**. Вставьте целиком содержимое `migrations/0001_stage1_prototype.sql` → Execute. Затем так же `migrations/0002_live_telegram_test.sql`. Каждый файл выполняется **один раз**.
3. **ID базы в проекте.** В файле `wrangler.jsonc` замените `REPLACE_WITH_D1_DATABASE_ID` на ваш Database ID.
4. **Публикация.** Загрузите содержимое папки проекта в репозиторий GitHub (через сайт). В Cloudflare: Workers & Pages → Create → импорт репозитория → Deploy. Сборку выполняет Cloudflare, на ваш компьютер ничего не ставится.
5. **Секреты.** Worker → Settings → Variables and Secrets → добавьте как **Secret**:
   - `ADMIN_TOKEN` — придуманный длинный пароль для входа в панель (20+ символов);
   - `APP_SECRET` — случайная строка 24+ символов для шифрования сессии. **Не меняйте её потом**, иначе сохранённый вход придётся делать заново.
6. **Ключи Telegram.** На `my.telegram.org` → API development tools → создайте приложение → скопируйте `api_id` и `api_hash`. Их можно вставить прямо в панели (вкладка «Аккаунт Telegram», шаг 1) — они сохранятся зашифрованными.
7. Откройте адрес вашего Worker (`…workers.dev`), введите `ADMIN_TOKEN`.

## Первая проверка (5–10 минут)

1. Вкладка **Аккаунт Telegram** → **Запустить проверку** (диагностику). Все пункты должны быть зелёными.
2. Сохраните ключи → **Показать QR-код** → в телефоне: Настройки → Устройства → Подключить устройство → сканируйте.
3. Вкладка **Мониторинг** → «Выбрать из моих чатов» → добавьте группу (и канал с комментариями).
4. Условия: включите «Любое сообщение» (для проверки связи) **или** впишите слова. Нажмите **Проверить**.
5. Вкладка **Тестовая база** → записи на месте → **Скачать Excel** → файл открывается, колонки те, что нужны.
6. Верните нормальные слова, нажмите **Запустить мониторинг** и напишите в группу пробное сообщение с этим словом (лучше с другого аккаунта) — через интервал проверки человек появится в базе.

Для тестов лучше использовать **отдельный или запасной аккаунт**: Telegram может ограничить аккаунт, который ведёт себя как робот. Программа читает редко (раз в интервал, с паузами) и при просьбе Telegram «подождать» сама останавливается на нужное время.

## Лимиты бесплатного тарифа

Мониторинг каждые 30 с — это ~2 900 запусков в сутки; по моей оценке это укладывается в бесплатные квоты Durable Objects и D1 для тестов (фактический расход смотрите в панели Cloudflare). Минимальный интервал в панели — 15 с. Excel собирается в браузере, чтобы не упереться в лимит процессорного времени бесплатного Worker.

## Структура

- `public/` — интерфейс (`app.js`, `qr.js` — генерация QR без внешних библиотек, `lib/xlsx.js` — сборка Excel).
- `src/worker.js` — API; `src/tg/` — Telegram-движок (`engine.js` логика входа и мониторинга, `gramjs.js` адаптер библиотеки, `do.js` Durable Object, `store.js` весь SQL).
- `migrations/` — `0001` (этап 1) и `0002` (этот шаг).
- `tests/` — тесты разработчика (`ui_harness.mjs` + `ui_e2e.py` — проверка интерфейса в браузере на имитации Telegram).
- `docs/` — архитектура, модель данных, ограничения Telegram и Cloudflare, протокол приёмки.
